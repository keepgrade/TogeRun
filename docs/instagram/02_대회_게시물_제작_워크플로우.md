# 대회 게시물 제작 워크플로우

> 대회 하나를 입력으로 받아 카드뉴스 PNG 3장과 캡션을 만드는 절차.
> 규칙은 `01_대회소개_게시글_가이드라인.md`를 따른다. 이 문서는 "어떻게 만드는가"만 다룬다.
> 첫 사례: 제2회 안양천 단풍길 마라톤 (`captions/2026-11-14_안양천단풍길마라톤.md`)

## 전체 흐름

```
대회 이름/공식 URL
  → 1. 정보 수집 (Playwright로 공식 사이트 읽기)
  → 2. 이미지 판정 (해상도 확인, 쓸 수 있으면 사용 / 아니면 자체 디자인)
  → 3. 카드뉴스 렌더링 (race-card.html → PNG 3장)
  → 4. 캡션 작성 (가이드라인 템플릿)
  → 5. 게시 전 점검 (체크리스트)
  → 6. 예약 게시 (Meta Business Suite) + 재게시 일정 등록
```

## 1. 정보 수집

- 입력: 대회 이름 또는 공식 홈페이지 URL
- 검색 포털(네이버 등)은 **대회 공식 홈페이지 주소를 찾는 용도**로만 쓴다. 포털 카드의 요금·일정은 종종 낡거나 다르다. (안양천 대회는 네이버 카드 요금이 공식 사이트와 달랐다.)
- 도구: Playwright MCP로 공식 사이트를 열어 본문 텍스트를 읽는다. 읽기만 하고 저장하지 않는다.
- 추출 항목: 대회명, 날짜·요일, 출발 시각, 장소, 종목, 참가비, 접수 기간(시각 포함), 혜택, 주최·주관, 유의사항
- 공식 사이트에 없는 항목(도착지, 정원, 제한시간 등)은 **적지 않는다.** 캡션에 `[확인 필요]`로 남기고 게시 전 채운다.
- 개인정보(입금자 명단, 연락처 등)가 보이면 **읽지도 저장하지도 쓰지도 않는다.**
- 확인한 날짜와 URL은 캡션 파일 상단에 기록한다.

## 2. 이미지 판정

```
후보 수집: og:image, 본문 이미지, 포스터
  → 가로 1080px 이상인가?
      예  → "주최 측 허락"이 있는가?
              예  → 사용 가능
              아니오 → 허락 요청(DM·메일) 전까지 사용하지 않음
      아니오 → 사용하지 않음 (AI 확대도 하지 않는 것이 기본)
  → 기본값: 투게런 자체 디자인 카드뉴스
```

- 포털 썸네일은 대부분 작다. 원본 주소(`src=` 파라미터)를 풀어도 업체가 올린 원본이 작으면 같다. (안양천 대회: 원본 103×145px)
- 확대(업스케일)는 2~4배까지만 쓸 만하고 글씨가 틀리게 복원될 수 있어 기본 절차에서 뺀다.
- 노션 캘린더의 `이미지 사용 허락` 칸: 필요 / 요청함 / 허락 받음 / 불필요(자체 디자인)

## 3. 카드뉴스 렌더링

템플릿: `cards/race-card.html` (1080×1350, 4:5)

| 장 | id | 내용 |
|---|---|---|
| 1 | `#c1` | 표지: 대회명, 훅, 날짜, 장소 |
| 2 | `#c2` | 정보표: 일정·장소·종목·참가비·접수·혜택 + 공식 확인 문구 |
| 3 | `#c3` | 투게런 CTA (모든 대회 공통) |

### 새 대회로 바꾸기
1. `race-card.html`의 문구만 교체한다. (대회명, 훅, 날짜, 정보 행)
2. 정보 행은 항목마다 `.row`를 추가·삭제한다. 6행까지는 한 장에 들어간다. 더 많으면 정보를 2장으로 나눈다.
3. 스타일은 건드리지 않는다. 색은 앱 토큰(`--brand` #ea580c, `--brand-soft` #fff7ed)을 쓴다.

### PNG로 뽑기
Playwright MCP는 `file:` 주소를 막으므로 임시 서버로 연다.

```bash
cd docs/instagram/cards
python -m http.server 8765 --bind 127.0.0.1
```

1. Playwright로 `http://127.0.0.1:8765/race-card.html?v=<숫자>`를 연다. (`?v=`는 캐시 회피용이라 수정할 때마다 바꾼다.)
2. `#c1`, `#c2`, `#c3`를 요소 단위로 스크린샷 저장한다.
3. 저장 경로는 작업 폴더 기준으로 풀리는 점에 주의한다. 상대 경로로 `out/card-1.png`를 주면 **저장소 루트의 `out/`에 생길 수 있으니** 저장 후 위치를 확인해 `cards/out/`으로 옮긴다.
4. 끝나면 서버를 끄고 `.playwright-mcp/`(Playwright 임시 파일)는 커밋하지 않는다.

### 렌더 결과 점검
- 글자가 잘리거나 워터마크(`@togerun_official`, 쪽번호)와 겹치지 않는가 (정보가 많으면 2장으로 분리)
- 제목이 3줄 안에 들어가는가
- 오탈자, 이모지 깨짐

## 4. 캡션 작성

- `01_대회소개_게시글_가이드라인.md`의 템플릿(3장)과 해시태그 규칙(4장)을 그대로 쓴다.
- 파일 위치: `captions/<대회일>_<대회명>.md`
- 파일에 적는 것: 출처 URL과 확인일, 연결된 카드 파일, 게시 전 재확인 항목, 이미지 허락 상태, 캡션 본문, 메모(생략한 항목과 이유)
- 접수 마감이 7일 이내면 `⏰ 접수 마감 D-n`을 훅 앞에 붙인다.

## 5. 게시 전 점검

가이드라인 7장 체크리스트를 따른다. 특히:
- 게시 **당일** 공식 사이트에서 접수 상태·참가비를 다시 확인한다.
- 레퍼런스 계정(런조아 등)의 문장을 쓰지 않았는지 본다.
- 카드 2장의 숫자와 캡션의 숫자가 같은지 본다.

## 6. 게시와 재게시

- 게시: Meta Business Suite(무료)로 예약한다. 이미지 3장 + 캡션.
- 재게시 일정: 접수 마감 7일 전, 3일 전 (가이드라인 6장)
- 노션 콘텐츠 캘린더(`콘텐츠_캘린더.csv`)에 날짜와 상태를 갱신한다.

## Claude에게 시키는 문장

```
docs/instagram 의 가이드라인과 워크플로우 문서대로
[대회명] 게시물을 만들어줘.
공식 URL: [URL] (모르면 대회명으로 공식 사이트부터 찾아줘)
```

Claude가 하는 일: 공식 사이트 읽기 → 이미지 판정 → 카드 PNG 3장 → 캡션 파일 → 점검표 결과 보고.
사람이 하는 일: 결과 확인, 게시 당일 재확인, 예약 게시, 이미지 허락 요청.

## 자주 막히는 곳

| 증상 | 원인과 해결 |
|---|---|
| 수정했는데 PNG가 그대로 | 브라우저 캐시. URL 뒤 `?v=` 숫자를 바꿔 다시 연다. |
| PNG가 엉뚱한 폴더에 생김 | 스크린샷 경로가 작업 폴더 기준이라 그렇다. 저장 후 위치를 확인한다. |
| `file:` 주소가 열리지 않음 | Playwright 제한. 임시 로컬 서버를 쓴다. |
| 네이버 검색 주소가 내장 브라우저에서 막힘 | 내장 브라우저는 막히고 Playwright MCP로는 열린다. |
| 카드 2가 넘침 | 정보 행을 줄이거나 2장으로 나눈다. |
