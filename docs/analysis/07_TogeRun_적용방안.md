# TogeRun 적용 방안

런조아 분석 결과를 [PRD](../PRD.md)와 비교했습니다. 런조아를 복제하는 것이 아니라, 무엇을 참고하고 무엇을 직접 설계할지 가르는 문서입니다.

## 1. 한눈에 보는 포지셔닝

- 런조아: "대회를 찾는다" (정보 탐색, 접수는 외부)
- TogeRun: "같이 나갈 사람을 찾는다" (대회 정보는 입구, 동행 연결이 목적)

## 2. 기능 비교

| TogeRun PRD | 런조아 현황 | 판단 | 비고 |
| --- | --- | --- | --- |
| FR-01 대회 목록(이름, 일시, 장소, 종목, 참가비, 접수 기간) | 같은 필드를 카드로 제공(SCR-003) | 변형 | 필드 구성은 유사하게 가되 표현은 TogeRun 방식으로 |
| FR-02 지역·종목·시기 필터 | 접수 상태, 규모, 연도, 월, 거리, 지역, 종류 필터(SCR-002) | 채택(축소) | MVP는 지역·종목·시기 3개만. 규모·종류는 보류 |
| FR-03 캘린더 | 월간 달력, 날짜 클릭 시 목록(SCR-004) | 채택 | 날짜 셀은 대회가 많아 "+N개 더보기" 처리가 필요 |
| FR-04 접수 오픈·마감·대회일 구분과 D-day | 접수 마감 D-day와 개최 D-day를 따로 표기 | 채택 | 추가 접수 일시 필드도 검토 |
| FR-05 관심 대회 저장 | 소개·약관에 명시, 화면 미확인 | 직접 설계 | 모집글과 연결된 저장으로 차별화 |
| FR-06 접수 알림 | 소개 문구만 확인 | 직접 설계 | 알림 시점은 PRD의 미정 항목 |
| FR-07 내 캘린더에 추가 | 베타(작동 안 함, SCR-017) | 직접 설계 | .ics 파일 방식이 외부 로그인 없이 구현 쉬움(제안) |
| FR-08~12 모집글, 오픈채팅 연결 | 없음 | 직접 설계 (TogeRun 핵심) | 대회 상세에 모집 현황을 넣는 위치만 참고 |
| FR-12 신고·차단 | 없음(사용자 간 상호작용 자체가 없음) | 직접 설계 | 운영정책의 "이용자 안전" 조항 구조를 참고 가능 |
| FR-13 정보 오류 제보·등록 문의 | 4유형 폼(SCR-010) | 채택(변형) | 공식 출처 링크 첨부 방식이 유용. 유형은 2개로 축소 가능 |
| FR-14 운영자 관리 | `/admin/` 비공개(미확인) | 직접 설계 | 좌표 변환 도구(SCR-016)처럼 입력 보조 도구 필요 |
| 지도 | 지도 API 미연결 | 제외(후순위) | PRD에 없음. 필요해지면 그때 검토 |
| 블로그·뉴스레터 | 운영 콘텐츠 채널 | 제외 | 모집 플랫폼에는 우선순위 낮음 |
| 연도별 아카이브 | 지난 대회 표(SCR-015) | 제외(후순위) | 후기·동행 이력으로 대체 가능 |

## 3. 가져올 만한 패턴

1. **접수 상태 칩과 마감 임박 표기:** "접수 예정·접수중·접수 마감" 3단계와 "오늘 마감", "마감 D-N" (홈과 목록 공통)
2. **홈의 3구획:** 접수 임박, 이번 달, 지금 접수 중. TogeRun 홈에는 "모집 중인 동행"을 추가합니다.
3. **카드 정보 밀도:** 날짜, 상태, 대회명, 장소, 종목, 참가비를 한 카드에. 모집글 뱃지(`하프` `현장 합류` `수원`)를 같은 방식으로 얹습니다.
4. **공식 출처 우선 정책:** 정보가 충돌하면 주최 측 공지를 우선한다는 원칙과 수정 요청 때 출처 링크를 받는 방식
5. **상세 하단 추천 구획:** 상세 하단에 접수 예정·접수중 목록을 노출해 체류를 늘리는 구성
6. **상태 계산:** 개최일·접수일에서 상태를 계산하고, 취소·연기만 수동 입력

## 4. 피해야 할 점

- 런조아의 문구, 이미지, 로고, 포스터는 쓰지 않습니다(PRD 저작권 요구사항). 대회 포스터도 권리자가 따로 있으므로 TogeRun은 텍스트 정보 중심이 안전합니다.
- 화면 구성은 참고하되 레이아웃과 비주얼은 독자적으로 설계합니다.
- 런조아의 대회 데이터를 그대로 긁어 쓰지 않습니다. 대회 정보는 주최 측 공식 출처에서 직접 수집하고 출처를 기록합니다. 런조아 이용약관의 데이터 이용 조항은 별도로 확인하지 못했으므로, 데이터 재사용 전에 약관과 운영 정책을 직접 읽어 보세요.
- 지도 API 연결, 외부 캘린더 로그인 연동처럼 런조아가 베타로 둔 기능을 MVP 범위에 넣지 않습니다.

## 5. 우선순위 제안

| 순서 | 항목 | 이유 |
| --- | --- | --- |
| 1 | 대회 목록·필터·상세(접수·마감·대회일 3종 날짜) | 모든 기능의 바탕. 런조아 패턴 그대로 검증됨 |
| 2 | 모집글 작성·목록·오픈채팅 연결 | TogeRun의 존재 이유. 런조아에 없음 |
| 3 | 관심 대회 저장 + 접수 알림 | 런조아도 재방문 부족을 약점으로 인정. 알림이 핵심 재방문 장치 |
| 4 | 신고·차단·운영 규칙 고정 | 낯선 사람 연결이라 안전 장치가 필수 |
| 5 | 정보 오류 제보 폼, 운영자 입력 도구 | 데이터 품질 유지 |
| 6 | 캘린더 보기, 내 캘린더에 추가 | 보조 탐색 수단 |

## 6. PRD에 반영을 검토할 항목

- 대회 데이터에 **추가 접수 일시** 필드 추가 여부
- 규모·참가비 **값 없음** 상태 표기 규칙
- 접수 상태 4단계(접수 예정·접수중·접수 마감·종료)와 취소·연기 수동 상태
- 모집글 폼의 "정보 수정 요청" 연결(대회 정보 오류 발견 시 바로 제보)

## 7. 한계

- 런조아의 회원 기능과 알림은 화면으로 확인하지 못했습니다. 이 비교에서 해당 행은 문서 문구에만 근거합니다.
- 런조아의 사용자 의견이나 불만은 조사하지 않았습니다.
